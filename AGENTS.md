# ShlokiTV project preferences

- Keep ShlokiTV customizations on the `shlokitv` fork branch and preserve the daily upstream release sync and deployment workflow.
- For relevant upstream bugs, check existing issues and pull requests first. The project owner authorizes contributing simple, well-tested fixes upstream when there is no existing PR addressing the issue. Keep upstream contributions focused and exclude ShlokiTV branding and deployment changes.
- Use the `unslop` skill for PR titles and descriptions. If the skill is unavailable, request its location and leave PR creation pending; do not claim to have used it.
- Include the concrete problem, resulting behavior, validation, and material limitations in PR descriptions.
- Never commit account credentials, environment secrets, or session data.
